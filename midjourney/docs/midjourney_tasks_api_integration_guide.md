# Midjourney Tasks API Integration Guide

The main function of the Midjourney Tasks API is to query the execution status of tasks by inputting the task ID generated by any Midjourney generation API (Imagine, Edits, or Videos).

This document provides detailed integration instructions for the Midjourney Tasks API, helping you easily integrate and fully utilize its powerful features. With the Midjourney Tasks API, you can query the execution status of tasks and retrieve results in asynchronous workflows.

## Application Process

To use the Midjourney Tasks API, you first need to apply for the corresponding service on the application page [Midjourney Imagine API](https://platform.acedata.cloud/documents/midjourney-imagine), and then copy the task ID from a Midjourney generation API response.

If you have not logged in or registered, you will be automatically redirected to the [login page](https://platform.acedata.cloud) inviting you to register and log in. After logging in or registering, you will be automatically returned to the current page.

There is a free quota available for first-time applicants, allowing you to use this API for free.

## Request Example

The Midjourney Tasks API can be used to query the results of the Midjourney Imagine, Edits, or Videos APIs. For information on how to use those APIs, please refer to their respective documentation.

We will use one task ID returned by the Midjourney Imagine API as an example to demonstrate how to use this API. Suppose we have a task ID: `a1b2c3d4-e5f6-7890-abcd-ef1234567890`. Below is a demonstration of how to query by passing in a single task ID.

### Setting Request Headers and Request Body

**Request Headers** include:

- `accept`: Specifies that the response should be in JSON format, set to `application/json`.
- `authorization`: The key to call the API, which can be selected directly from the dropdown after application.

**Request Body** includes:

- `id`: The task ID to query.
- `action`: The operation type. Use `retrieve` for a single task query (default).
- `trace_id`: An optional trace ID to query by trace.

### Code Example

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/midjourney/tasks' \
-H 'accept: application/json' \
-H 'authorization: ******' \
-H 'content-type: application/json' \
-d '{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/midjourney/tasks"

headers = {
    "accept": "application/json",
    "authorization": "******",
    "content-type": "application/json"
}

payload = {
    "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Response Example

Upon successful request, the API will return the detailed information of the task. For example:

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "request": {
    "prompt": "A cat sitting on a table",
    "action": "generate",
    "mode": "fast"
  },
  "response": {
    "success": true,
    "image_id": "1234567890abcdef",
    "progress": 100,
    "image_url": "https://cdn.acedata.cloud/midjourney/result.png",
    "image_width": "2048",
    "image_height": "2048",
    "raw_image_url": "https://cdn.acedata.cloud/midjourney/result_raw.png",

```

The returned result contains multiple fields. The `request` field is the request body when the task was initiated, and the `response` field is the response body returned after the task is completed. The field descriptions are as follows:

- `id`: The ID of the task, used to uniquely identify this task.
- `request`: The request information in the queried task.
- `response`: The return information in the queried task.

## Batch Query Operation

This is for querying the details of multiple task IDs. Unlike the above, the `action` needs to be set to `retrieve_batch`.

**Request Body** includes:

- `ids`: An array of task IDs to query.
- `trace_ids`: An optional array of trace IDs to query by trace.
- `action`: The operation type for the task, set to `retrieve_batch`.
- `offset`: The starting position for pagination. Default is `0`.
- `limit`: The maximum number of results to return. Default is `12`.

### Code Example

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/midjourney/tasks' \
-H 'accept: application/json' \
-H 'authorization: ******' \
-H 'content-type: application/json' \
-d '{
  "ids": ["a1b2c3d4-e5f6-7890-abcd-ef1234567890", "b2c3d4e5-f6a7-8901-bcde-f12345678901"],
  "action": "retrieve_batch"
}'
```

### Response Example

Upon successful request, the API will return the specific details of all batch tasks. For example:

```json

      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
```

The returned result contains multiple fields. The field descriptions are as follows:

- `items`: All specific details of the batch tasks. It is an array, with each element having the same format as the single task query response.
- `count`: The number of tasks in this batch query.

## Error Handling

When calling the API, if an error occurs, the API will return the corresponding error code and message. For example:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.

### Error Response Example

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
